# 从小车动力学，到 OSQP 的矩阵

建议把 `dynamics.py` 和 `controller.py` 放在旁边对照。这里的每个量都能在 `uv run mpc-demo inspect` 的输出或 JSON 中找到。

## 1. 先定义“预测一步”

沿轨道方向，小车满足 `m * dv/dt = u`，`dp/dt = v`。输入 u 的单位是 N，位置 p 是 m，速度 v 是 m/s。没有摩擦、阻尼或沿轨道的重力分量。

MuJoCo 采用 Euler 积分。本例没有速度相关力，所以每个物理子步 h 的更新是：

```text
v_(j+1) = v_j + h*u/m
p_(j+1) = p_j + h*v_(j+1)
```

在 n 个子步内保持推力不变：

```text
v_next = v_now + n*h*u/m
p_next = p_now + n*h*v_now + (h²/m)*(1+2+...+n)*u
       = p_now + dt*v_now + h²*n*(n+1)/(2m)*u
```

因此 `dt=n*h`，A/B 就是：

```text
A = [[1, dt],       B = [[h²*n*(n+1)/(2m)],
     [0, 1 ]]            [dt/m           ]]
```

`h=.005, n=10, m=1` 时，B 位置项为 `.001375`。连续时间零阶保持的精确解位置项 `.5*dt²/m=.00125`，二者的区别来自数值积分。对这个简单模型，可以精确匹配数值仿真，不必将积分误差当成 MPC 的问题。

`test_discrete_prediction_matches_actual_mujoco` 在多组质量、子步数与随机推力下验证这一点。若给 XML 加上阻尼、非线性弹簧或接触，这个模型就需要修改。

## 2. 从一步到 N 步

在某次控制更新时刻，把测得的状态记为 x0。这里的 x0 不是整段实验的初始状态，而是**当前这一拍**的状态。

```text
x1 = A x0 + B u0
x2 = A² x0 + AB u0 + B u1
x3 = A³ x0 + A²B u0 + AB u1 + B u2
...
```

把 x1 到 xN 堆成列向量 X，把 u0 到 u_(N−1) 堆成 U：

```text
X = F x0 + G U

F = [ A  ]       G = [ B        0      0  ... ]
    [ A² ]           [ AB       B      0  ... ]
    [ A³ ]           [ A²B      AB     B  ... ]
    [ ...]           [ ...                    ]
```

每个小块 B 有两行一列。N=40 时，F 是 80×2，G 是 80×40，U 是 40 维，X 是 80 维。`prediction_matrices()` 用两个小循环按这个公式构造。

`free = F @ x_now` 表示从当前状态开始，未来不给任何推力时会怎样；`G @ U` 则是未来推力产生的增量。x0 已知，不是优化变量。X 已被消去，只有 U 与松弛量 S 是优化变量，这叫 condensed 写法。

## 3. 为什么要把位置和速度都写进代价？

设未来参考状态是 ri。停车时 ri=[目标位置,0]。代价为：

```text
J = sum(i=1..N-1) (xi-ri)' Q (xi-ri)
  + (xN-rN)' Qf (xN-rN)
  + r_force * sum(i=0..N-1) ui²
  + r_delta * [(u0-u_previous)² + sum(i=1..N-1)(ui-u_(i-1))²]
  + slack_quadratic * S'S + slack_linear * 1'S
```

Q=diag(20,1)，Qf=3Q。Qf 替代最后一拍的 Q，不重复叠加。位置、速度、推力单位不同，这些权重定义了我们希望优化的折中，不能直接把数值大小当成物理上的相同重要程度。

只罚位置会更愿意用较大末端速度换取暂时接近目标；罚速度才能表达“停住”。只罚当前一步可能太短视，末端代价让窗口最后仍关心停车，但单靠任意终端权重不自动得到稳定性保证。

令 Qbar=diag(Q,...,Q,Qf)，R 为堆叠参考，D 为主对角线 1、下对角线 −1 的 N×N 矩阵。令 previous=[u_previous,0,...,0]，则相邻输入差为 `D U-previous`。

## 4. 把目标展开成求解器认识的形式

代入 `X=F x0+G U`，令 `e=F x0-R`：

```text
(X-R)'Qbar(X-R)
= U'G'Qbar G U + 2 e'Qbar G U + e'Qbar e
```

最后一项与 U 无关，不影响最优动作，可以删掉。平滑项同样展开。得到：

```text
H = G'Qbar G + r_force*I + r_delta*D'D
q_u = 2*(G'Qbar e - r_delta*D'previous)
```

OSQP 求解 `min 1/2 z'Pz + q'z`，所以：

```text
z = [U, S]
P = block_diag(2H, 2*slack_quadratic*I)
q = [q_u, slack_linear*ones]
```

注意 `1/2` 带来的系数 2。在本例 r_force>0、松弛二次权重>0，Hessian 正定，问题是严格凸 QP。`test_unconstrained_qp_matches_independent_finite_horizon_riccati` 用无约束动态规划的独立实现检查这个目标的最优输入，避免两份相同矩阵代码互相“验证”。

## 5. 把约束写成 l ≤ C z ≤ upper

未来状态的上界向量 b=[p_max,v_max,...]，下界为 −b。软约束逐元素允许放宽：

```text
−u_max ≤ U ≤ u_max
X − S ≤ b
−X − S ≤ b
S ≥ 0
```

代入 X 的表达式：

```text
C = [ I     0  ]   lower = [−u_max]   upper = [ u_max      ]
    [ G    −I  ]           [−inf  ]           [ b−F x0     ]
    [−G    −I  ]           [−inf  ]           [ b+F x0     ]
    [ 0     I  ]           [ 0    ]           [+inf        ]
```

每个预测节点有位置和速度两项松弛，所以 S 长度为 2N；总决策变量长度为 3N。硬输入约束不可放宽，状态界限则可以放宽但会受到惩罚。当前 x0 不强制落在界限内，未来每一步都会被检查。

这也解释了为什么从超速初始状态仍然能求解：物理上暂时避不开的违反可以交给 S 表达。报告中显示的是数值计划实际需要的松弛，逐元素 `max(|X|−b,0)`；不是声称每个状态都满足原始界限。

没有模型误差/外力时，预测能准确对应下一状态。有未知外力时，即使预测软约束几乎不松弛，实际状态也可能越界；此时控制器只能在下一拍测得新状态后恢复。真实安全要求可能需要鲁棒 MPC、约束收紧与可验证的后备控制。

## 6. 每一拍到底重算什么？

`MPC.__init__()`：算 A/B、F/G、Qbar、D、P 和 C，初始化 OSQP。固定模型和固定权重下，这些结构可以复用。

`MPC.solve(x_now, reference)`：

1. 重新读 x_now 后计算 `free=F@x_now`。
2. 根据本拍参考更新 `q_u`；根据 x_now 更新状态约束上界。
3. 将上一拍输入计划左移，作为本次初值，不作为必须执行的指令。
4. 调用 OSQP；要求状态为 `solved`，否则明确报错退出。
5. 提取 U，按数值容差做极小裁剪，再回算预测状态与所需松弛。

固定模型的矩阵并不需要每拍重新推导。未来状态、参考偏差、最优计划则每拍都会变。热启动减少重复计算，不能替代求解。

求解器得到的整个 U 是一组**此刻最合理的未来打算**。`simulate()` 只使用 U[0]，真实仿真运行 dt，然后重新进入这一过程。

## 7. 外力那一拍，可以怎样手算与核对？

默认未知推力在 t=3.00 到 3.20 s，为 +4 N，持续 4 个控制周期。若质量为 1 kg，每个周期会额外增加约 0.2 m/s 的速度。预测器没有外力项，因此：

```text
上一拍预测：x_pred = A*x_now + B*u0
实际下一拍：x_real = A*x_now + B*(u0+4)
差值：B*4 = [0.0055 m, 0.2 m/s]
```

在 `examples/01_minimal_loop.py` 的 t=3.00 s 输出中，可以直接看到这个差值。下一拍 MPC 读到 x_real，再安排制动。开环则保留原来的 U；从静止附近受到的总速度增量约为 0.8 m/s，后面持续漂移。

如果模型质量也错了，误差除了外力还包含质量不匹配。每次优化能利用新测量，但并不会自动学会正确质量。

## 8. 换成更复杂系统时

本例有一个便利条件：动力学线性，二次目标与线性约束构成凸问题。更复杂机器人常用以下路径：

- 在平衡点线性化，仍用线性 MPC，但只在局部有效。
- 沿当前预测轨迹反复线性化，结合 SQP 等方法。
- 直接用非线性预测与约束做 NMPC，可能有局部极小值与更高计算成本。
- 用采样、CEM、MPPI 等方法优化动作序列；它们仍可以遵循同一滚动执行思想。

优化算法可以改变，“基于当前状态看未来、执行首项、重新测量与规划”保持不变。这个项目把这条主线拆开，便于你迁移时知道究竟要替换哪一层。
